# myopensupports 實作計畫

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal：** 新增 `myopensupports` 技能，用序號列出、產生安裝方案、移除本倉庫 `open_supports/` 支持包，並以 `sync`／`add` 維護本機清單。

**Architecture：** 單一 Python 3 腳本 `dot_claude/skills/myopensupports/scripts/myopensupports`（只用標準庫，結構仿 `myplugins`），讀 `$AGENT_RULES_REPO` 下的 INDEX、場景清單、安裝腳本註解與摘要；本機清單存 `~/.claude/myopensupports/catalog.json`。`install` 只印方案；`remove` 預設只印方案，帶 `--apply` 才備份並刪除。SKILL.md 負責把方案轉給使用者並用 AskUserQuestion 讓使用者選參數與執行方式。

**Tech Stack：** Python 3 標準庫；POSIX sh 測試。

**Spec：** `docs/plans/2026-11-05-myopensupports-design.md`

## Global Constraints

- 倉庫只取自 `AGENT_RULES_REPO`；有效條件：`<R>/scripts/install-open-supports.sh` 與 `<R>/open_supports/INDEX.md` 都存在。否則印 `錯誤：` 行並以退出碼 2 結束，不退回其他方式找倉庫。
- 排除 `ost_GithubName_RepoName_TEMPLATE` 與 `.claude-FLAG-NAME_template`。
- 不執行任何安裝腳本或上游卸載命令；不修改倉庫內容；不改專案的 `open_supports_name_list.txt`。
- 使用者可見輸出、SKILL.md、details.md 用繁體中文；`錯誤：`、`注意：` 前綴與 myplugins 一致。
- 測試用環境變數：`MYOPENSUPPORTS_HOME`（清單目錄，預設 `~/.claude/myopensupports`）、`MYOPENSUPPORTS_PROJECT_DIR`（預設 `CLAUDE_PROJECT_DIR`，再退回目前目錄的 git 根目錄，最後退回目前目錄）。
- 生成標記取 `install-open-supports.sh` 的原字串：`<!-- generated by scripts/install-open-supports.sh; delete this line to keep manual edits -->`。
- 備份目錄：`<專案>/.claude/open_supports.backup-<YYYYmmdd-HHMMSS>/`。
- 專案級參數判定：參數含 `{PROJECT_DIR}`、`--local` 或 `--location=local`。

## Review Focus

1. INDEX 表格某列格式不同（缺欄、包名沒加反引號）→ 該列略過並印 `注意：`，不讓整個 list 崩潰。測試放在 Task 1。
2. 序號超出範圍或包名不存在 → 印 `錯誤：` 並退出 2，不印半份方案。測試放在 Task 3。
3. `remove --apply` 對未安裝的包 → 印「目標專案未安裝」，不建立空的備份目錄。測試放在 Task 4。
4. `AGENT_RULES_REPO` 帶結尾 `/` 或 `~` → 正常解析（展開 `~`、正規化路徑）。測試放在 Task 1。
5. 自訂參數含空格 → `install-open-supports.sh` 不支援，印 `錯誤：`。測試放在 Task 3。

### Task 3：install 方案

**Files：** Modify：腳本；Test：同一份測試檔。

**Interfaces：**
- Consumes：`resolve`、`is_global_only`、`project_dir`、`locate_repo`。
- Produces：
  - `default_args(repo, pkg) -> list[tuple[str, str]]`：回傳 `(參數字串, 來源說明)`，依序取：
    1. 只能全域的包：全域清單的行。
    2. 場景清單 `dot_claude_projects/.claude-*/.claude/open_supports_name_list.txt` 的行；整行註解的行去掉 `#` 後，第一個詞是已知包名（Owner/Repo 或 ost_）才算。
    3. 安裝腳本示例。全域包取第一條不含路徑的示例，其他包取第一條含 `/path/to/project` 或 `TARGET_DIR` 的示例，並把路徑換成 `{PROJECT_DIR}`。
    4. 都沒有時回傳空 list。
  - `script_help(repo, pkg) -> str | None`：取 `scripts_for_install/install.*` 開頭註解中 `# 用法` 到下一個 `# ====` 或非註解行之間的內容，去掉 `# `。
  - `build_command(repo, proj, pkg, args: str) -> str`：依 Global Constraints 的專案級判定，產生 `sh <R>/scripts/install-open-supports.sh -t <P> -n <upstream> -- <args>`；否則若屬只能全域的包，產生 `-g -n <upstream> [-- <args>]`；非全域包又沒有專案級參數時，仍用 `-t`。
  - `cmd_install(repo, cat, sel, custom: str | None)`

- [ ] **Step 1：寫失敗測試。** 準備假倉庫：
  - `ost_a_one/scripts_for_install/install.sh`，註解含 `# 用法：`、`# 示例：`、`#   ./install.sh --target=claude /path/to/project`。
  - 場景清單 `.claude-backend-dev`，其中 `ost_o_spec` 的行為 `o/spec --init-project {PROJECT_DIR}`。
  - 全域清單含 `g/glob --global`。

  斷言：

  - `ost_o_spec` 用 `-t`，來源註明 `backend-dev`。

  - `cmd_remove(repo, cat, sel, apply: bool)`

- [ ] **Step 1：寫失敗測試。** 專案內建立 `.claude/open_supports/ost_a_one/x`、帶生成標記的 `.claude/skills/ost_a_one_install/SKILL.md`，以及 `.claude/open_supports_name_list.txt`（含 `a/one`）。摘要檔含 `- 卸载：\`one uninstall\``。斷言：
  - `remove 1`：列出兩個路徑，印出含 `--apply` 的完整命令，含 `one uninstall`，含 `注意：` 清單重裝提示，檔案仍在。
