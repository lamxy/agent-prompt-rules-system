# open_supports Usage Examples Optional Stage Design

## Goal

Optimize `open_supports/.copilot-skills/` so support packages can keep
`repo_readme_summary.md` concise while optionally generating a dedicated
post-install usage guide when a library has enough workflow depth to justify it.

This design also clarifies the uninstall boundary for one-click install scripts.

## Decisions

1. `repo_readme_summary.md` Part 3 remains a quick-reading example section.
   It may include limited explanatory notes that help a reader understand what
   each example does, but it must not become a multi-scenario tutorial.
2. Detailed usage examples are generated by a new optional Skill,
   `ost-usage-examples`, rather than being folded into the summary or setup Skill.
3. The optional usage stage runs only when a fixed checklist suggests that the
   library has meaningful post-install workflows, and the user approves it.
4. Uninstall behavior is not part of default one-click install scripts. Official
   uninstall instructions should be recorded as reference material. A script
   may support `--uninstall` only when official uninstall behavior is clear and
   the user explicitly asks for that extension.

## Workflow Shape

The workflow becomes:

```text
repo_readme_summary
-> install_script
-> skill_for_setup
-> optional_usage_examples
-> optional_test_install
```

`optional_usage_examples` does not block the core support package. If the
checklist does not justify it, or if the user declines it, the stage is marked
`skipped`.

## Optional Usage Examples Trigger

After `skill_for_setup` is complete, the workflow checks whether at least two of
these conditions are true:

- The library exposes a CLI or executable commands.
- The library has a project initialization flow.
- The library uses configuration files or a local state directory.
- The library integrates with Agent, MCP, IDE, Copilot, Claude, Codex, or similar
  clients.
- The library has common post-install workflows beyond a one-time command.
- The official README or documentation includes multiple usage scenarios.
- `.ost-refs/` defines local usage conventions.

If two or more conditions match, the workflow asks the user whether to generate
`usage_examples.md`. The question should explain the detected reasons and state
that this does not affect the core install support package.

## New Skill: ost-usage-examples

Add:

```text
open_supports/.copilot-skills/ost-usage-examples/SKILL.md
```

The Skill writes:

```text
open_supports/ost_{GithubName}_{RepoName}/usage_examples.md
```

The Skill should read, in order:

1. The target package's `repo_readme_summary.md`
2. The target package's `skill_for_setup/README.md` and setup `SKILL.md`
3. The target package's `scripts_for_install/install.*`
4. The target package's `.ost-refs/` directory, if present
5. Official README or documentation links referenced by the summary, when needed

It must use the same Clarification / Blocking protocol as the existing stage
Skills. If a command, workflow, or client integration cannot be confirmed from
official or local reference material, it returns a blocked clarification instead
of guessing.

## usage_examples.md Structure

Use this structure:

```markdown
# {LibraryName} — 使用示例

> 來源：官方 README / 文檔；本文件只保留 open_supports 使用者最常見的入口。

## 快速開始
## 常見場景
## 與 Agent 客戶端配合
## 驗證與排錯
## 延伸閱讀
```

Each example should include:

- Scenario: when to use it
- Command or minimal configuration
- Expected result: what success looks like
- Notes: only execution-relevant limits or caveats

The document must not:

- Copy large portions of official documentation
- Invent commands not supported by official or local reference material
- Rewrite installation steps already covered by `repo_readme_summary.md` Part 2
  and `scripts_for_install/install.*`
- Include uninstall workflows as executable guidance

## Existing Skill Updates

### ost-repo-readme-summary

Update Part 3 guidance to require minimal examples with limited explanatory
notes. Add checklist items confirming that examples are understandable but have
not expanded into a multi-scenario tutorial.

### ost-install-script

Add an uninstall policy:

- Default install scripts do not include destructive uninstall behavior.
- Official uninstall instructions may be referenced.
- `--uninstall` is allowed only as an explicit, optional extension when official
  behavior is clear and the user asks for it.

Add a quality check confirming that destructive delete or uninstall logic was
not added by default.

### ost-skill-for-setup

Clarify that setup Skills focus on installation, configuration, verification,
and upgrade entry points. If `usage_examples.md` exists, the completion message
may point users to it. Troubleshooting may link to official uninstall
documentation, but should not execute uninstall steps by default.

### ost-support-workflow

Add `optional_usage_examples` after `skill_for_setup` and before
`optional_test_install`. This stage:

1. Evaluates the trigger checklist.
2. Asks the user before generation when two or more conditions match.
3. Dispatches `ost-usage-examples` as a serial stage subagent if approved.
4. Records `done`, `skipped`, `blocked`, or `failed` in workflow state.

## Documentation Updates

Update `open_supports/workflow-plan.md` so the documented state machine matches
the Skill behavior.

Update `open_supports/README-todo.md` to:

- Mark the three clarified questions as resolved.
- Explain the boundary for `open_supports/.copilot-skills/`: reusable
  cross-package Skills belong there, while library-specific install Skills stay
  under each package's `skill_for_setup/`.
- Record `ost-usage-examples` as an optional reusable Skill.

## Out of Scope

- Generating `usage_examples.md` for existing support packages during this
  design step
- Running install scripts
- Editing generated support package outputs unless requested separately
- Adding uninstall behavior to existing scripts by default

## Acceptance Criteria

- `repo_readme_summary.md` examples remain concise but clearer to skim.
- A new optional `ost-usage-examples` Skill defines consistent output and
  blocking behavior.
- Workflow docs and Skill instructions describe `optional_usage_examples`.
- Install script guidance clearly treats uninstall as reference-only by default.
- No core workflow completion depends on generating usage examples.
