# 场景基础人设评估（2026-11-06）

结论：**不采用**。场景 `CLAUDE.md` 加一句人设，没有可测的收益，配置不改动。

## 起因

网友分享的 8 套研发结构化提示词（全栈 MVP、代码库重构、排障、系统设计、性能、整洁架构、多智能体、UI 组件）。用户提议从中提取四个场景的基础人设，用于增强专注力，并确认了两点：放在场景 `CLAUDE.md` 标题下一行，先评估收益再决定是否处理。把 8 套提示词做成任务模式技能的方案，用户已取消。

## 书面依据

- Anthropic《Prompting best practices》「Give Claude a role」：在 system prompt 中设定角色，会让 Claude 的「行为与语气」更聚焦。文中没有说能提高正确率。
- Zheng 等，EMNLP 2024 Findings（arXiv 2311.10054）：162 个角色、4 个模型系列、2410 道事实题，加人设不提升表现，效果「很大程度是随机的」。研究对象是事实问答，不是 agent 编程。
- 本仓库：通用人设 agent 在 72 个会话中调用 0 次（`agents/README.md`）；阶段 3 的 16 个任务全部通过，现有任务存在天花板效应。

## 测试

方法：
- 复制阶段 3 专案（`scenario-eval-final`）的对应 tag 到 scratchpad，用 `claude -p` 无人值守跑同一提示词。
- 有人设组在 `CLAUDE.md` 第 2 行后插入一句人设，无人设组不改。
- Claude Code 2.1.318，共 12 个会话，约 US$5.8。

人设草稿：
- prd-design：资深产品经理兼 UX／UI 设计师
- frontend-dev：资深前端工程师（为防过度设计，不加全栈）
- dev-ops：资深 DevOps／SRE，负责环境设计、部署运维与排障

| 任务 | 观察点 | 结果 |
|---|---|---|
| P1 | 先问目标用户、核心场景、成功指标 | 两组都通过；有人设组多问了约束 |
| P4 ×2 轮 | 是否在浏览器实测 | 第 1 轮无人设组测了、有人设组没测，第 2 轮正好相反，属随机 |
| D2 | 先查资源与现有环境、`.env`、配置预览 | 两组相当 |
| F5 ×2 轮 | 页面状态、响应式、无障碍 | 第 1 轮有人设组略好，第 2 轮两组相当 |

判定规则是「至少 2 项改善，且没有退步，复测仍成立」，本次未达标。看到的改善都是把人设句里写明的行为照做，角色身份本身没有体现出额外作用。

## 限制

- 无人值守模式下，追问没有人回答。
- 每个条件只跑 1～2 次。
- D2 为了防止真的启动容器，禁用了 `Bash(docker volume*)` 等命令，结果两组的只读同名项目检查也被一并拦下。这是测试设置造成的干扰。
