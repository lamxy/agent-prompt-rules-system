# 覆盤規則

使用者輸入 `/mysession-eval review [場景] [--final]` 時照本檔執行。不帶 `--final` 為**期中覆盤**，帶 `--final` 為**最終覆盤**。

## 1. 取得匯總

```sh
python3 ~/.claude/skills/mysession-eval/scripts/mysession-eval summarize
```

指定場景時加 `--scenario <FLAG>`。只用這份輸出判斷，不讀日誌原檔。`bad_lines` 大於 0 時在報告開頭註明。

## 2. 判定規則

依據：設計稿 `docs/plans/2026-11-05-mysession-eval-design.md` 第 8、9 條，與評估計畫 3.5 判定表（通過／調整／移除）。

- **場景整體**：`scenario_eligible` 為假時，整體只寫「尚不能判斷，還差 N 筆」（N 取 `scenario_missing`），不下判定。達標時看推定滿意度分布（3.5「滿意度 ≥ 4」）與 `interventions_trend`（後半平均低於前半視為下降；`n` 不足 4 寫「趨勢樣本不足」）。
- **單一配置**（`items` 中每項）：只看客觀訊號，不用滿意度。
  - `item_eligible` 為假：歸入「尚不能判斷」，寫出還差幾筆（門檻 `item_threshold`）。
  - 可用訊號：裝了卻從未使用（`records_used` 為 0）、`missed` 次數、`denials_by_tool` 集中在某工具、rule 該載入未載入。注意 Bash 的 `head`／`cat` 讀檔不會載入 rule（2.1.318 實測），rule 未載入不一定代表 rule 有問題。
  - 同一配置有多個 `hash` 時是前後兩版，分開陳述；改動後版本未達門檻時寫「改動後樣本不足，尚不能判斷」，不與舊版合算。
  - `tool_errors.sandbox` 只計錯誤訊息含 `Operation not permitted` 的情況；其他由沙箱造成的錯誤（例如 Go 快取被擋，訊息只有 `Exit code 1` 或下游報錯）只計入總數。判斷錯誤是否屬環境問題時參考各筆備註，不只看這個計數。
  - `settings`、`claude_md` 沒有使用次數，只做定性：看 `missed` 與匯總中能反映的訊號，不硬給判定。
- **`used_not_installed`**：多半是全域配置，列出供參考，不判定。
- **建議門檻**：提出「調整／移除」必須寫出配置檔路徑、具體改法、依據的筆數；說不出改法或證據不足的現象歸入「觀察中」。
- **沒有發現問題**時照實寫，並列出看過的面向與各自筆數。不為了湊結論降低標準。

## 3. 基線對照（只做定性）

環境變數 `AGENT_RULES_REPO` 有設定時，讀 `$AGENT_RULES_REPO/docs/evaluation/2026-10-baseline.md` 與 `2026-10-final.md` 的問題清單，標出在試用中再現的項目。不比數字（基線是標準任務，不是真實專案）。未設定時略過並註明。

## 4. 輸出結構

1. 場景判定（或「尚不能判斷，還差 N 筆」）
2. 建議：調整／移除（路徑、改法、依據筆數）
3. 觀察中
4. 尚不能判斷（配置與差額）
5. 推定滿意度分布（`dist`、`by_source`），請使用者對照自己的感受；不符時表示推定方法要修
6. 基線對照（若有）

## 5. 期中與最終的差別

- **期中覆盤**：結論標「階段性」，不寫回任何倉庫檔案。使用者決定是否調整配置。
- **最終覆盤**：完成上述報告後，另擬一段寫入 `docs/evaluation/2026-10-final.md` 試用章節的文字。去識別化：專案目錄名換成 `<場景>-<序號>`（如 `backend-dev-1`），不含真實專案名、原始碼、秘密值。先給使用者看，確認後才寫入與提交。
