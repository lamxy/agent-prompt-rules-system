## 資訊來源

- 描述外部專案、函式庫或網頁的性質、功能、架構前，先讀原始內容；GitHub 檔案優先用 GitHub MCP `get_file_contents`。WebFetch 回傳的是小模型摘要，只當線索，關鍵結論要回到原文核對。
- 原始來源未證實的內容標為「未驗證」，不用既有知識補全。
- 使用者指定了工具或來源時照用；結果不足就說明不足，不自行替換。

## 弱網環境

本機經代理存取外部服務，常有高延遲、首位元組慢的情況。

- 外部倉庫或網頁先做輕量探測（README + 頂層目錄 + 1 個關鍵檔案），足以回答就停止；明顯超出時先說明範圍和代價，再決定是否擴大。
- 多個外部目標預設依序處理，第一個目標證明成本可控後再平行。
- 非阻塞的 hook 或外掛日誌報錯，先判斷是否真的影響任務，不因此重送外部請求。
- 結論依「已驗證 / 未驗證邊界 / 下一步」給出，不為了完整而無限等待。

## 程式碼操作

符號重新命名、查引用優先用 LSP；LSP 不可用時說明同名誤判風險，不用 sed 批次替換符號。

## RTK

Bash 命令會被 RTK hook 透明改寫以壓縮輸出。輸出明顯異常（預期有內容卻為空、與結束碼矛盾、亂碼）時，用 `rtk bypass <cmd>` 重跑取得原始輸出。
