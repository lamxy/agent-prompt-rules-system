# 安装作用域契约测试用例

本用例集用于审查 `ost-install-script` 的输出设计，不运行真实安装命令。

## Case 1：仅全局安装

官方命令不接受项目路径，且只安装到用户级目录。

- 分类必须为 `A（仅全局）`。
- 安装器默认直接执行官方全局命令；不得伪造 `--target` 或项目本地模式。
- 帮助、摘要和 setup Skill 都必须说明会写入用户级目录。

## Case 2：CWD 决定的项目本地安装

官方 CLI 提供 `tool add --local`，把内容写到当前目录的 `.tool/`，且不支持项目路径参数。用户从任意目录调用封装脚本，目标项目是 `/work/app`。

- 分类必须为 `B（项目本地／CWD 敏感）`。
- 安装器必须接收项目目录位置参数，默认 `.`，并先解析为绝对目录、验证目录存在。
- 执行本地命令必须使用 `( cd "$ABS_TARGET_DIR" && tool add --local )`；不得 `cd` 后遗留改变调用端工作目录。
- `--global` 必须是显式 opt-in，并且不能错误依赖目标目录。
- 帮助和关联文档必须给出 `/work/app` 这类明确目标目录示例。

## Case 3：原生命令接受项目路径

官方 CLI 提供 `tool add --project /work/app`，写入该项目。

- 分类必须为 `C（原生路径参数）`。
- 安装器必须优先把已验证的绝对目标目录交给 `--project`，而不是依靠自己的 `cd` 模拟。
- 默认目标仍为 `.`，并且保持调用端工作目录。

## Case 4：同时支持全局与项目模式

官方命令默认全局，`--local` 启用写入当前项目目录的安装。

- 分类必须为 `D（双模式）`，默认行为必须完全匹配官方默认，不能一律改成 local。
- local 分支适用 Case 2 或 Case 3 的目录规则；global 分支不接收无意义的项目路径。
- `repo_readme_summary.md`、安装脚本、setup Skill、usage examples 与 workflow dispatch contract 必须表达同一分类和默认值。

## 验收方法

针对每个新支持包，先从官方一手资料记录分类、默认值、是否 CWD 敏感、是否支持路径参数及证据 URL；再逐项比对本用例。任一事实无法确认时必须阻塞澄清，不得猜测。
