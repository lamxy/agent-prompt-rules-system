# 工具调用极简规约

适用于主场景已确定后，为补足关键事实、证据或执行必要操作而进行的工具读取、检索、验证、修改或多工具联合处理场景。

规则：
- 本规约不用于决定任务主场景，只在主场景已确定且确需补充证据时按需叠加。
- 仅在值得时调用工具。
- 先判断当前上下文是否足以稳定回答；若足够，则不调用工具。
- 若仅缺一个关键事实，优先追问一个最关键的问题，而不是直接调用工具。
- 工具调用用于补足关键事实，不用于替代主场景判断、澄清、推理或原始来源验证。
- 工具输入尽量精确、聚焦、最小化。
- 工具输出先压缩、筛选、去重，再写回主会话。
- 不把完整原始输出、长日志、长列表、长 JSON、整份 diff 回灌到主线。
- 多工具结果先去重，再汇总。
- 主会话只保留结论、关键证据、风险和下一步。
- 若无需工具即可可靠回答，不额外调用工具。
- Read 文件结果：只摘录与当前决策直接相关的行，不展示完整文件内容。
- 若外部网络质量差、Fast mode 不可用、首字节显著缓慢或代理稳定性不足，优先采用降级策略：先读 README、目录或单一关键文件，不做完整爬取。
- 外部仓库分析默认优先“轻量探测”而非“全量抓取”：先验证一个最小来源是否足够，再决定是否扩大范围。
- 若外部证据范围预计超过“轻量探测”预算，先停止扩张并向主代理报告范围、成本与风险；必要时由主代理请求用户确认后再继续。
- “轻量探测”预算默认指：单个目标的 README、顶层目录，以及 1 个最关键文件或页面；超出该范围视为扩大检索。
- 同一轮若已有外部调用明显变慢，避免继续并行增加 GitHub、网页或子代理请求。
- 出现非阻塞型 hook 错误日志时，先区分任务结果与 hook 噪音；不得仅因 hook 噪音就重复整个外部调用链。
- 若某次外部工具调用已足以形成可用结论，优先带着不完美证据结束，而不是为了完整性继续扩张调用。

推荐格式：
[tool-summary]
result=<结论>
evidence=<关键证据>
risk=<low|medium|high>
next=<下一步>
