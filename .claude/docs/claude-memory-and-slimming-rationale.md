# Claude 记忆机制与提示词瘦身说明

## 1. 目的

本文用于沉淀以下内容：

- 为什么本仓库要做提示词瘦身。
- 本次具体改了什么。
- 采用的 Claude Code 官方记忆/加载规则依据。
- 后续维护可复用的检查清单。

范围仅覆盖本仓库运行时提示词与记忆加载行为。

---

## 2. 问题定义

瘦身前主要存在两处不一致：

1. 设计意图与实际加载不一致
- `CLAUDE.md` 的意图是“按需加载”。
- 但 `.claude/rules/*.md` 中大量文件没有 `paths` frontmatter，实际属于启动阶段候选加载。

2. 运行时策略与维护说明混杂
- 运行时高优先规则与维护说明写在同一个常驻文件里。

对应风险：

- 启动 token 消耗偏高。
- 规则噪音增加，冲突概率上升。
- 运行时策略与文档说明边界不清。

---

## 3. 已执行改动

### 3.1 主运行文件瘦身

- 将 `.claude/CLAUDE.md` 收敛为运行时最小策略。
- 仅保留高频、高杠杆规则。
- 补回精简映射块：
  - 主场景 -> 规约文件
  - 模板用途 -> 模板文件
  - 模板启用条件

### 3.2 非运行时文档迁出 rules 自动加载域

- 模板原文迁移到 `.claude/expandable/templates/`。
- 审计原文迁移到 `.claude/expandable/audit/`。
- 同步更新 `README.md` 与 `.claude/CLAUDE.md` 的路径说明。

### 3.3 维护备注低成本保留

- 在 `.claude/CLAUDE.md` 中使用 HTML 注释块承载维护者备注。

## 4. 强制证据来源（Claude 官方文档）

来源页：`https://code.claude.com/docs/en/memory`

用于决策的关键规则：

1. 无 `paths` 的 rules
- 属于启动阶段加载候选，近似项目指令层行为。

2. 有 `paths` 的 rules
- 在处理匹配路径文件时触发，不是每次工具调用都触发。

3. CLAUDE.md 加载行为
- 当前目录与祖先目录中的 CLAUDE 文件是启动上下文候选。
- 子目录 CLAUDE 文件是懒加载（读到对应目录文件时触发）。

4. `@path` 导入行为
- 导入内容会在启动时展开并进入上下文。
- 用导入拆文件仅改善组织，不天然降低启动负载。

5. HTML 注释行为
- CLAUDE.md 中的块级 HTML 注释在注入前会被剥离。
- 代码块内注释不会被剥离。

6. 运行时验真方式
- 可通过 `/memory` 查看当前会话实际加载的 CLAUDE/rules 与 auto memory 状态。

## 5. 当前仓库策略

1. 运行时策略文件
- `.claude/CLAUDE.md` 保持最小常驻。

2. 规则层
- 场景与偏好规则保留在 `.claude/rules/task/` 与 `.claude/rules/preferences/`。

3. 文档层
- 模板与审计说明保留在 `.claude/expandable/`。

## 6. 官方存储与记忆文档总结

### 6.1 两套记忆机制

- `CLAUDE.md` 体系：用户编写的指令记忆。
- Auto memory：Claude 在项目维度写入的学习笔记。

### 6.2 作用域与优先级（实践视角）

- 组织托管策略（managed policy）优先级最高，且不能被本地排除。
- 项目/用户/本地指令按发现路径叠加。
- 同目录内 `CLAUDE.local.md` 会追加在 `CLAUDE.md` 之后。

### 6.3 排除与边界

- 可用 `claudeMdExcludes` 排除指定 CLAUDE/rules 路径。
- managed policy CLAUDE 不可排除。

### 6.4 额外目录行为

- `--add-dir` 默认不会加载新增目录中的 memory 文件。
- 需要显式环境变量开关才会加载。

### 6.5 子代理

- 子代理可维护自己的持久 auto memory。
- 关键约束应显式放在有效提示词路径，不应仅依赖“可能继承”。

### 6.6 对本仓库的落地含义

- 运行时主提示词应短、稳、可执行。
- 解释性与维护性文本应迁入 expandable 层。
- 仅在确有路径条件时使用 scoped rules。
- 用 `/memory` 做加载验真，而不是凭假设。

---

## 7. 维护检查清单

后续调整记忆/规则架构时，推荐按以下顺序检查：

1. 这是运行时必须常驻的吗？
- 不是则放 expandable，不放常驻提示词。

2. 这是路径条件规则吗？
- 是则优先使用 `paths` frontmatter。

3. 这是维护者备注吗？
- 优先放 CLAUDE.md 的 HTML 注释块。

4. 启动负载是否上升？
- 复查无 `paths` 规则与导入文件。

5. 实际加载是否符合预期？
- 用 `/memory` 做最终验真。
